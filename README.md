# Hi, I'm Wutthichai

I build things that ship — a habit-tracking app released as an Android APK, a fighting game two
people can play across the internet with no game server, and a dashboard that watches every
automation running on my machine.

First-year Computer Science student. I write most things from scratch in plain code, and I build the
measurement so I find out when something *isn't* working.

---

### Projects

**[SakuraQ](https://github.com/sacmaib80-cmyk/sakuraq)** — A quest-style focus timer that turns study
sessions into points. Shipped as an Android APK and an installable web app.
`Vanilla JS PWA · Capacitor · Firebase`

**[AI Flow](https://github.com/sacmaib80-cmyk/ai-flow)** — A live map of every automation running on
my machine, built so it can't show data it hasn't verified.
`Node · WebSocket · SQLite`

**[Pixel Clash](https://github.com/sacmaib80-cmyk/pixel-clash)** — A pixel fighting game two people
can play across the internet with a 4-character room code. No game server.
`React · Canvas · WebRTC`

**[Moonfall](https://github.com/sacmaib80-cmyk/moonfall)** — A social-deduction game where the bots
lie, hunt, and vote against you.
`Vanilla JS · Canvas · A*`

**[SakuraQ Native](https://github.com/sacmaib80-cmyk/sakuraq-native)** — SakuraQ rewritten as a
native Android app, with unit tests.
`Kotlin · Jetpack Compose`

**[Code Dojo](https://github.com/sacmaib80-cmyk/code-dojo)** — A 157-exercise coding drill site I
built to tutor my classmates before an exam.
`Single-file HTML/JS`

### How I work

I ship the whole thing myself — design, code, build, release. When something I made isn't working I'd
rather find out from data than from a feeling, so I tend to build the tracking before I build the
next feature.
